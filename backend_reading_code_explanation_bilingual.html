Scope

1. What This Backend Is Responsible For

The backend does not only store book metadata. It creates the database schema, imports readable content, answers API requests for books/chapters/pages, and builds playable audio for each chapter.

English summary

The reading backend has one main job: move book content from raw source files into MySQL tables, then expose that content through FastAPI endpoints so the app can read and listen to it.

الملخص بالعربية

المهمة الأساسية لهذه الخلفية هي نقل محتوى الكتب من ملفات المصدر الخام إلى جداول MySQL، ثم تقديم هذا المحتوى عبر واجهات FastAPI لكي يستطيع التطبيق قراءته والاستماع إليه.

Reading pipeline

  1. Create the database tables
  2. Insert catalog books
  3. Import readable text into `chapters` and `pages`
  4. Expose chapters and pages through API routes
  5. Generate chapter audio when requested

مسار القراءة

  1. إنشاء جداول قاعدة البيانات
  2. إدخال كتب الفهرس
  3. استيراد النص المقروء إلى `chapters` و`pages`
  4. تقديم الفصول والصفحات عبر الواجهات البرمجية
  5. توليد صوت الفصل عند الطلب
In this project, a book becomes “readable” only when it has rows inside the `chapters` table and matching rows inside the `pages` table.

العربية: هاتان الدالتان هما ما يجعل الكتاب قابلاً للقراءة فعلياً. إذ يتم أولاً حذف الصفوف القديمة الخاصة بالفصول والصفحات والصوت، ثم إدخال الفصول الجديدة إلى `chapters`، وإدخال كل فقرة أو صفحة إلى `pages`.

`GET /chapters/{chapter_id}/audio`

English: This route is the final audio endpoint. It checks whether chapter content exists, builds a file name based on book/chapter/voice, looks for a cached audio row, generates audio when missing, writes the path into `chapter_audio`, and finally returns a complete public media URL.

The first audio request may be slow because the backend is generating the file. Later requests become faster because the route can return cached audio.

7. Full Backend Reading Flow From Source File To App Screen

This is the clearest way to explain the complete backend code during presentation.

Step 1: raw source file exists

Files: `import_book.py` or `import_amwaj_akma.py`

English: The project begins with a raw JSON or page source file that still needs cleanup.

العربية: يبدأ المشروع من ملف مصدر خام بصيغة JSON أو صفحات نصية تحتاج إلى تنظيف وتنظيم.

Step 2: source is cleaned and normalized

Files: `import_book.py`, `import_amwaj_akma.py`

English: The import code repairs encoding, removes noise, groups content into chapters or sections, and prepares a structured list.

العربية: يقوم كود الاستيراد بإصلاح الترميز وحذف الضجيج وتجميع المحتوى في فصول أو أقسام ثم إعداد قائمة منظمة.

Step 3: tables are guaranteed to exist

Files: `catalog_utils.py`, `main.py`

English: The backend ensures that the schema exists before writing or serving anything.

العربية: تتأكد الخلفية من وجود الجداول قبل كتابة أي شيء أو تقديمه للتطبيق.

Step 4: readable content is written

Files: `catalog_utils.py`

English: The content is inserted into `chapters` and `pages`, which is the real moment when a book becomes readable in the app.

العربية: يتم إدخال المحتوى في `chapters` و`pages`، وهذه هي اللحظة الحقيقية التي يصبح فيها الكتاب قابلاً للقراءة داخل التطبيق.

Step 5: the frontend requests chapters/pages

Files: `main.py` endpoints

English: The backend returns ordered chapter and page rows so the app can display the reading UI.

العربية: تعيد الخلفية صفوف الفصول والصفحات مرتبة حتى تتمكن الواجهة من بناء شاشة القراءة.

Step 6: audio is generated on demand

Files: `main.py`, `chapter_audio` table

English: The backend transforms chapter text into speech, stores the MP3 path, and returns a URL to the app.

العربية: تحول الخلفية نص الفصل إلى كلام، وتحفظ مسار MP3، ثم تعيد للرابط إلى التطبيق.

Key Points

8. What To Say About The Full Backend Code

These are the strongest technical ideas inside this backend.

Readable books are data-driven

The backend does not mark a book readable by hand in the API layer. A book becomes readable because chapter and page rows were imported into the database.

قابلية القراءة مبنية على البيانات

لا تقوم الخلفية بتحديد الكتاب كقابل للقراءة يدوياً داخل الواجهة البرمجية، بل يصبح الكتاب قابلاً للقراءة لأن الفصول والصفحات تم استيرادها فعلاً إلى قاعدة البيانات.

Schema creation is built into runtime

The server guarantees the required tables at startup, which makes demo deployment and testing easier.

إنشاء الجداول جزء من التشغيل

يضمن الخادم وجود الجداول عند الإقلاع، وهذا يسهل العرض والتجربة والاختبار في بيئة المشروع.

Audio is a real backend service

The audio feature is not just a frontend button. It includes text preparation, language detection, chunking, provider selection, cache control, file storage, and public URL generation.

الصوت خدمة خلفية حقيقية

ميزة الصوت ليست مجرد زر في الواجهة، بل تشمل تجهيز النص، وتحديد اللغة، وتقسيم المحتوى، واختيار مزود الصوت، والتحكم بالكاش، وتخزين الملف، وإنشاء الرابط النهائي.

Import scripts are part of the product

The book import scripts are essential, because without them the app would have catalog entries but no full readable content.

سكربتات الاستيراد جزء من المنتج

تعد سكربتات الاستيراد جزءاً أساسياً، لأنه من دونها سيبقى التطبيق مجرد فهرس كتب بلا محتوى كامل قابل للقراءة.

Final summary: the backend makes reading possible by creating the schema, importing structured content into chapters/pages, serving those rows through API endpoints, and generating cached audio from the same text.
