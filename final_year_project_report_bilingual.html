Overview

1. Project Overview and Objectives

Books Library was designed as a bilingual book application that presents English and Arabic titles in a modern, lightweight, and extendable format. The app does more than display catalog data: it allows users to browse, search, save favorites, create accounts, read available titles inside the application, and listen to chapter audio generated on demand.

The central objective of the project is to demonstrate a complete digital reading system rather than a static interface. For that reason, the work is divided into clear layers: a Flutter frontend, a FastAPI backend, a MySQL data store, content import scripts, media caching for audio, and Firebase-based authentication for user access.

Flutter + Dart FastAPI + Python MySQL Firebase Auth Audio Playback English / Arabic UI
Current seed configuration in the backend defines 100 English titles and 10 Arabic titles, while two books are imported as fully readable content in the app build.

Implemented Scope

2. Main Features Delivered

Curated bilingual home dashboard

The home screen loads catalog statistics, featured books, readable books, English books, Arabic books, and curated classics from backend data.

Dynamic search and filtering

Users can search by title or author and filter results by all books, readable books, English books, or Arabic books.

Personal favorites

Each book can be saved to favorites. The selection persists locally across sessions using `shared_preferences` on native platforms and `localStorage` on web.

Authentication and profile

Email and password sign-up, sign-in, sign-out, and profile display are implemented through Firebase Authentication.

Book details and reading state

Every title opens a detailed bottom sheet showing language, chapters, pages, description, and whether the book is fully readable or catalog-only.

In-app reading experience

Readable titles can be opened inside the app, where chapters and their page content are loaded and presented in a long-form reading layout.

Per-chapter audio generation

The chapter page can request MP3 narration from the backend, choose between Rachel and Adam voices, and control playback with play, pause, resume, and stop.

Runtime language switching

The entire interface can switch between English and Arabic using the in-app language toggle without rebuilding the project.

Main shell

A floating bottom navigation bar organizes the app into Favorites, Home, and Search. This creates a simple and memorable navigation structure.

Home page

Displays summary cards, featured titles, readable books, English and Arabic sections, and a curated grid, which helps users understand the library quickly.

Shows favorite books only, creating a personalized shelf that survives app restarts.

Shows authenticated account data such as email and UID, plus logout functionality.

Acts as the main decision point for each title by presenting metadata, chapter/page counts, reading availability, and a primary action button.

Backend

5. Backend Services, API Design, and Database

The backend is implemented with FastAPI and starts by ensuring the required schema exists in MySQL. This keeps deployment simple: the app can initialize the database structure automatically when the server starts instead of relying on a separate migration system for this project stage.

The main API endpoints are:

  • `GET /books`: returns the full catalog with language, featured state, chapter count, page count, and readability state.
  • `GET /books/summary`: returns total books, readable books, English books, and Arabic books for the dashboard cards.
  • `GET /books/{book_id}/chapters`: returns the chapter list for a selected book.
  • `GET /chapters/{chapter_id}/pages`: returns page content for one chapter.
  • `GET /chapters/{chapter_id}/audio`: generates or reuses a chapter MP3 file and returns a playable media URL.
Database Table Purpose Stored Data
`books` Master catalog Title, author, description, language, featured flag, sort order, created date
`chapters` Readable structure Book-to-chapter relationship, chapter number, chapter title
`pages` Readable content units Page number and text content for each chapter
`chapter_audio` Audio cache index Voice-specific generated audio path for each chapter
The audio table uses a unique `(chapter_id, voice_name)` combination, which means the same chapter can cache different voices independently.

Audio Pipeline

6. Audio Generation and Media Strategy

The audio service is one of the strongest technical parts of the project. When a user opens a chapter and requests narration, the backend loads chapter pages, builds a clean narration script, detects whether the content is mainly Arabic or English, and then tries to create MP3 audio.

The preferred provider is ElevenLabs when its SDK and API key are available. If that is not possible, the backend falls back to Google Text-to-Speech (`gTTS`). This fallback design improves reliability and demonstrates practical engineering, because the app can still function even when premium voice generation is unavailable.

Generated audio is stored under the backend media directory and reused in future requests. As a result, the first request may take a few seconds, but later playback is faster because the app reads from cache instead of regenerating the file.

Rachel voice Adam voice Language detection Chunked text processing Cached MP3 output
The backend combines catalog APIs, media generation, caching, and static file serving in one coherent service layer.

Content Pipeline

7. Book Data Preparation and Import Workflow

The project does not rely only on manually typed catalog records. It includes dedicated Python scripts to prepare and import real readable content. This makes the system more realistic for a final year project because it demonstrates how raw source material can be transformed into structured application data.

English readable title import

`import_book.py` processes a clean JSON file for Alice's Adventures in Wonderland. It repairs misencoded text, normalizes headings, builds chapter entries, and writes the result into MySQL.

Arabic readable title import

`import_amwaj_akma.py` cleans raw Arabic page data, removes noise such as links and mixed-language artifacts, groups pages into sections, exports a generated JSON file, and imports the structured content into the database.

Seeded library catalog

`catalog_seed.py` inserts the full curated library list, applies featured ordering, resets old content when needed, and re-imports the readable titles so the app starts from a known academic demo dataset.

Catalog strategy

The app intentionally supports both catalog-only books and fully readable books. This allows the project to scale the library now while still expanding full-text content progressively later.

Flow

8. User Flow and Runtime Data Flow

Step User action System response
1 User opens the app Flutter initializes Firebase, loads favorites from storage, and shows the main shell.
2 User enters Home or Search `ApiService` requests catalog data and renders books using model classes.
3 User opens a book The details sheet displays metadata and decides whether reading is available.
4 User reads a title The app loads chapters and pages and builds a long-form reading view.
5 User requests audio The backend generates or reuses chapter audio, returns a URL, and the app streams it with `audioplayers`.

الخلفية وقاعدة البيانات

5. الخادم الخلفي والواجهات البرمجية وقاعدة البيانات

تم بناء الخادم الخلفي باستخدام FastAPI، ويقوم عند التشغيل بالتأكد من وجود الجداول الأساسية داخل قاعدة بيانات MySQL. هذا الأسلوب يجعل تشغيل المشروع أسهل في بيئة العرض أو المناقشة، لأن الخادم يستطيع تجهيز البنية المطلوبة تلقائياً.

أهم الواجهات البرمجية المنفذة هي:

  • `GET /books` لإرجاع جميع الكتب مع اللغة والحالة وعدد الفصول والصفحات.
  • `GET /books/summary` لإرجاع إحصاءات الصفحة الرئيسية.
  • `GET /books/{book_id}/chapters` لإرجاع فصول كتاب محدد.
  • `GET /chapters/{chapter_id}/pages` لإرجاع نص الصفحات التابعة لفصل معين.
  • `GET /chapters/{chapter_id}/audio` لتوليد أو إعادة استخدام ملف الصوت وإرجاع رابط التشغيل.
اسم الجدول الغرض نوع البيانات المخزنة
`books` الفهرس الرئيسي اسم الكتاب والمؤلف والوصف واللغة والترتيب والحالة المميزة
`chapters` هيكلية الكتاب ربط الكتاب بالفصول وأرقامها وعناوينها
`pages` النص المقروء رقم الصفحة والمحتوى النصي لكل فصل
`chapter_audio` فهرس كاش الصوت مسار ملف الصوت لكل فصل ولكل صوت مختار
يستخدم جدول الصوت مفتاحاً فريداً يربط الفصل باسم الصوت، لذلك يمكن حفظ أكثر من نسخة صوتية للفصل نفسه مثل Rachel وAdam.

يقوم سكربت `import_book.py` بمعالجة ملف JSON لكتاب Alice's Adventures in Wonderland، وإصلاح ترميز النص وتنظيم العناوين ثم كتابة الفصول داخل قاعدة البيانات.

استيراد الكتاب العربي

يقوم سكربت `import_amwaj_akma.py` بتنظيف الصفحات العربية الخام، وحذف الروابط والضجيج والآثار المختلطة، ثم تقسيم المحتوى إلى أقسام وتصديره أيضاً بصيغة JSON منظمة قبل إدخاله إلى القاعدة.

بذر المكتبة الكاملة

يستخدم `catalog_seed.py` لإدخال قائمة الكتب الكاملة مع الترتيب والتمييز وإعادة تحميل المحتوى المقروء، حتى تبدأ النسخة التجريبية للمشروع ببيانات واضحة ومضبوطة.

استراتيجية الفهرس

يدعم التطبيق حالتين: كتب متاحة كاملة للقراءة، وكتب موجودة في الفهرس فقط. هذا القرار يجعل المشروع قابلاً للتوسع التدريجي دون الحاجة إلى تجهيز النص الكامل لكل كتاب منذ البداية.

8. رحلة المستخدم وتدفق البيانات

الخطوة فعل المستخدم استجابة النظام
1 فتح التطبيق يتم تهيئة Firebase وتحميل المفضلة وعرض الهيكل الرئيسي للتطبيق.
2 الدخول إلى الرئيسية أو البحث تستدعي الواجهة بيانات الكتب من الخادم عبر `ApiService` ثم تعرضها باستخدام النماذج البرمجية.
3 فتح كتاب معين تظهر نافذة التفاصيل وتحدد هل الكتاب متاح للقراءة أم أنه ضمن الفهرس فقط.
4 بدء القراءة يتم تحميل الفصول والصفحات وبناء واجهة قراءة طويلة داخل التطبيق.
5 طلب الصوت يقوم الخادم بتوليد الصوت أو استرجاعه من الكاش ثم يعيد رابط الملف ليتم تشغيله داخل التطبيق.
6 تغيير اللغة أو إضافة كتاب للمفضلة تتحدث الواجهة مباشرة بفضل آلية إدارة الحالة الخفيفة المستخدمة في المشروع.
